## 1. Cacat Critical: siklus tertutup menghasilkan pohon kosong

Reviewer Task 3 menelusuri tes `siklus_dihentikan` secara manual dan menemukan
lubang desain yang tidak terlihat dari membaca kode saja.

**Skenarionya:** order OA menghasilkan material A dan memakan B; order OB
menghasilkan B dan memakan A. Siklus tertutup, tanpa akar dari luar.

**Yang terjadi:** aturan "akar = material yang tidak dipakai order lain"
menyisihkan **kedua** kandidat. `rt_node` kosong, `descend( )` tidak pernah
dipanggil, dan penjaga siklus yang justru dirancang untuk kasus ini tidak
pernah dieksekusi.

**Kenapa ini serius bukan cuma soal tes:** SO nyata dengan data RESB melingkar
akan menampilkan halaman kosong yang tidak bisa dibedakan dari "SO ini memang
tidak punya order". Diam, tanpa petunjuk apa pun.

**Keputusan:** pohon tidak boleh kosong secara diam-diam. Bila ada order tapi
deteksi akar tidak menemukan satu pun, **semua** order pembuat diperlakukan
sebagai akar dan diberi catatan `akar tidak terdeteksi (kemungkinan siklus)`.
Penjaga siklus di `descend( )` yang menghentikan rekursinya.

Aturan ini diangkat jadi **Global Constraint** (`56adf59`) supaya mengikat
task-task berikutnya, bukan hanya Task 3.

## 4. UI `index2.htm` diganti mengikuti `prototype/`

Permintaan user: UI dibuat **sama persis** dengan folder `prototype/`
(210 baris HTML + 287 JS + 472 CSS). Setelah UI beres, baru lanjut
memperbaiki pengambilan & tampilan data.

**Yang berubah secara mendasar:**

| Aspek | Sebelum | Sesudah |
|---|---|---|
| Judul | Lintasan Routing & Confirmation | Dashboard Production |
| Sumbu filter | SO | **Buyer** |
| Pusat produksi | 3 section (Machining/Edge Banding/Assembling) | **2 center**: Machining Center (40 WC) + Edge Banding & Sanding (20 WC) |
| Alur | rantai stasiun | Storage → Machining → Edge Banding → Storage |
| Panel baru | — | Filter Buyer, daftar SO/PLO |

**Font Awesome tidak bisa dipakai.** Prototype memuatnya dari CDN; jaringan
SAP tertutup sehingga ikon tidak akan muncul sama sekali. Diganti 19
`symbol` SVG inline dengan nama yang mengikuti nama ikon FA aslinya, supaya
mudah dicocokkan dengan prototype. Hasil visual sama, sumbernya beda — ini
satu-satunya titik di mana "sama persis" tidak bisa dipenuhi secara harfiah.

**Yang dipertahankan:** blok DATA LIVE dibawa **byte-exact** dari versi
sebelumnya (disalin dari berkas lama, bukan diketik ulang), jadi kartu
KOMPONEN dan CONFIRMED tetap memakai query MSKA/AFRU yang sudah jalan.

**Yang masih dummy:** kartu BUYER / DI PRODUKSI / SELESAI PROD. / BOTTLENECK,
filter buyer, dua kotak center, peta work center, daftar SO/PLO, tabel
Detail Komponen. Semuanya dikirim ke JS sebagai array di blok bertanda
`DATA DUMMY UNTUK JS` — fase data nanti cukup mengganti isi array itu tanpa
menyentuh logika filter/render.

⚠️ **Catatan definisi yang belum beres:** prototype menulis CONFIRMED =
"basis komponen diterima". Angka yang kita hitung berbasis **operasi**
ter-konfirmasi (AFRU). Sub-teks kartu sengaja tetap menyebut "op" supaya
tidak mengklaim hal yang belum dihitung. Ini pekerjaan fase data.

## 5. Bug: tag HTML literal di komentar ABAP

Menulis `<script>` dan `<link>` utuh di dalam komentar ABAP membuat parser
HTML editor mengira ada blok script terbuka di situ, lalu memparse **seluruh
sisa berkas sebagai JavaScript** — ratusan diagnostik palsu.

Tidak merusak BSP (BSP hanya peduli delimiter `<%`/`%>`), tapi meracuni
tooling dan menyembunyikan error sungguhan. Kelas masalah yang sama dengan
bug delimiter kemarin: **hati-hati menulis sintaks bahasa lain di dalam
komentar.** Diperbaiki dengan menulisnya tanpa kurung sudut.

## 6. `scripts/check_bsp.py`

Pemeriksa struktur berkas BSP dijadikan skrip tetap, bukan perintah sekali
pakai. Memeriksa: delimiter nyasar di blok ABAP, pasangan `<% %>` /
`<%-- --%>` / `LOOP` / `IF` / `CASE`, keseimbangan `div` & `span`, dan tag
HTML literal di komentar ABAP.

Dua alarm palsu ditemukan dan diperbaiki saat mengujinya ke halaman lain:

- `TRANSLATE ... TO UPPER CASE` terhitung sebagai pernyataan `CASE`
- penyebutan tag di dalam komentar CSS terhitung sebagai tag sungguhan

**Batas metode yang didokumentasikan di skripnya:** hitungan div/span hanya
sahih untuk halaman yang markup-nya tidak dipecah lintas cabang ABAP.
`monitoring.htm` membuka `div` di satu cabang `IF` dan menutupnya di cabang
lain — hitungan mentahnya wajar tidak seimbang, dan itu **bukan** cacat.
Halaman itu diperiksa manual dan terbukti sehat.
