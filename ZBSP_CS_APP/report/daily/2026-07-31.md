## 3. Bug yang ditemukan dan diperbaiki

**Aktivasi gagal — "Closing `%>` without opening `<%`" di baris 279.**
Penyebabnya contoh tag output BSP yang saya tulis di dalam komentar ABAP.
Parser berhenti pada delimiter tutup pertama yang ditemukannya, jadi scriptlet
terpotong di tengah dan sisa file diperlakukan sebagai HTML. Diperbaiki, dan
peringatannya ditulis permanen di komentar file supaya tidak terulang.

**Elemen inline mengabaikan CSS vertikal.** Beberapa elemen tooltip dan titik
dot ditulis sebagai `<span>` (agar nesting-nya valid) tapi CSS-nya
mengandalkan `height`/`margin` vertikal — yang diabaikan browser pada elemen
inline. Perlu `display:block`.

**Qty stok tercetak `48.000`.** `MSKA`/`MARD` bertipe QUAN 3 desimal. Dibuatkan
tabel tampilan terformat, karena `COLLECT` melarang field teks ikut di tabel
agregasi.

**Komponen tergabung salah.** Kalau Item dikosongkan, dua item SO yang memakai
material sama tergabung jadi satu lane. Diperbaiki dengan memasukkan `KDPOS`
ke kunci komponen.

## 4. Perombakan konsep: dari rantai jadi pohon

Disadari bahwa rantai stasiun lurus **salah menggambarkan proses**. Material
menyusut lewat penggabungan: 20 komponen dari Pembahanan digabung 5:1 di
Machining jadi 4, digabung 2:1 di Edge Banding jadi 2, digabung lagi di Sanding
jadi 1. Bentuk data yang benar adalah pohon konvergensi.

Sesi brainstorming menghasilkan keputusan berikut:

| Keputusan | Isi |
|---|---|
| Fokus halaman | Diagnosa hambatan — "kenapa tahap ini belum jalan" |
| Arti stok 0 | Dibedakan lewat `RESB-ENMNG`; tanpa ini order yang sudah selesai tampak tertahan |
| Scope order | Semua order SO+Item tanpa filter DISPO; yang di luar 7 nilai baku ditandai dan bisa disembunyikan lewat JS |
| Barang beli | Dibuang dari pohon |
| Tempat kode | Class baru `ZCL_CS_PEG`, halaman hanya menyajikan |
| Bentuk | Kartu stasiun sebagai ringkasan + tabel pohon sebagai tampilan utama |
| Arah pohon | Produk akhir di atas, bahan mentah di bawah |
| Interaksi | Kartu stasiun bisa diklik → panel rincian |

**Kunci teknisnya:** struktur pohon sudah ada di SAP lewat `RESB`. Order
menghasilkan satu material (`AFPO-MATNR`, qty `PSMNG`) dan memakan
komponen-komponennya (`RESB`: `BDMNG` butuh berapa, `ENMNG` sudah diambil
berapa). Rasio "5:1" itu literal `BDMNG / PSMNG`.

Hasilnya:
- Spec: `docs/superpowers/specs/2026-07-31-pohon-konvergensi-material-design.md`
- Rencana: `docs/superpowers/plans/2026-07-31-pohon-konvergensi-material.md`
